# 舊圖檢核修正（依舊界改正）

計算全部在工作站裡（`Core.trimExcess`／`planTrimExcess`），AI 只負責串流程、把需要判斷的列給使用者。**不要在工作站外面自己讀 COA／BNP 算坐標再回寫**：外算用的是單一仿射，比工作站的分幅對位粗，而且會與頁面狀態不同步（2026-10-29 因此漏接 T 字點 12449）。

## 流程

1. `workstation_status`：確認已連線、權限模式（ask／write）。唯讀就停下說明。
2. `save_milestone`（例「依舊界改正前」）。
3. `plan_old_map_trim`：一次拿到全部建議。
4. `recommend = unreg` 的：用 `trim_excess` 的 `items` 一次套用（`to: 'unreg'`，`mother` 照使用者指定，KC0336 用 9012）。
5. `recommend = review` 的：**不要自己決定**。把地號、目前→改正後面積、登記、切出面積、貼著的鄰宗列成表給使用者，問每筆要「建未登記地／併入哪一宗／不做」，照回答用 `trim_excess` 套用。
6. `recommend = skip` 的：不動；需要時用 `call_api setNote` 把原因寫進備註。
7. `live_check` 確認沒有交錯、重疊、T 字接點；`fix_queue_done` 標修好並附處理方式。
8. 給使用者一份報告（改了哪些、新增哪些未登記地、哪些需要他判斷），提醒存專案檔。

## 判斷規則（使用者 2026-10-29 在 KC0336 確立）

| 情況 | 處理 | 來源 |
|---|---|---|
| 接圖時界址被拉到接圖線，外側只貼著未登記地或段外 | 沿舊界切回，外側建未登記地；接圖線上的點不動，維持與鄰段密合 | 1096-1、117-1、117-2 |
| 切出的部分貼著別的登記地 | 先問使用者：常是鄰宗的範圍（應併入鄰宗），也可能本來就屬本宗 | 72-1 切出的屬 88-2；1022-1 外側屬 1022-1 本身 |
| 改正後面積離登記面積更遠 | 不做（舊圖本身不準，或已人工調整過；坐標帶很多位小數常是人工調整的痕跡） | 76-17、76-13 |
| 接圖前就不符 | 不做（不是接圖造成） | 96-15、149、1009-9 |
| 舊界址點在宗地外（被鄰地佔用）、共用點被接圖拉走 | 不自動做；要整群（共用點移回＋相鄰宗地一起）處理，列給使用者 | 120／120-1、1092-2～4、1088-6 |
| 差異只是圖解誤差（< 5 m²，或現況已在公差內） | 不切 | 385-28 |
| 使用者說「不用做」 | 還原（`mergeParcels` 把切出的未登記地併回），並從已修好名單取消（`confirmCheck {confirmed:false}`） | 1091-24 |

## 注意

- 權限 ask 模式下每個修改都會跳確認；使用者說「自動修、不用問」時請他把頁面權限改成「直接修改」，不要繞過。
- 共用點用 `addPoint` 加在線上（`edge`）時，所有以該線為界的宗地都會插點、面積不變；不要只改一邊。
- 一次回傳超過 20 萬字會被橋接截斷：用 `plan_old_map_trim` 這類整批工具，不要用 `listParcels`、`saveProjectJson` 撈全部資料。
